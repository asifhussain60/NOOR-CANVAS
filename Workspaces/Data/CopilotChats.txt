## 🔍 ARCHITECTURE ANALYSIS - Registration Bypass Vulnerability

### Current Violation
**Critical Security Gap:** Participants can reach SessionWaiting.razor, SessionCanvas.razor, and TranscriptCanvas.razor **without completing registration** by directly navigating to URLs with valid tokens.

### Root Cause Analysis

#### ❌ **Current Flawed Flow**

**UserLanding.razor** (Entry Point):
1. ✅ Token validation works (`/api/participant/session/{token}/validate`)
2. ✅ Registration gate exists (`CheckParticipantRegistrationAsync()`)
3. ✅ Atomic navigation logic implemented (lines 1078-1115)

**BUT...**

**SessionWaiting.razor** (Lines 995-1394):
- ✅ Calls `LoadCurrentParticipantFromApiAsync()` 
- ❌ **NO registration verification** - only looks up UserGuid from localStorage
- ❌ **If UserGuid is empty, continues anyway** (line 1344: `CurrentUserGuid = string.Empty;`)
- ❌ **Uses fallback token-only participant lookup** instead of rejecting unregistered users

**SessionCanvas.razor** (Lines 1726-1885):
- ✅ Calls `LoadCurrentParticipantFromApiAsync()`
- ❌ **Same vulnerability** - fallback token-only lookup (line 1842: "Don't set CurrentUserGuid")
- ❌ **Allows page load without registered participant**

**TranscriptCanvas.razor** (Lines 1488-1643):
- ❌ **Identical vulnerability** to SessionCanvas
- ❌ **No registration gate**

### Proposed Architecture/Approach

#### **Phase 1: Add Registration Guard to Session Pages**

**Concept:** Each session page (`SessionWaiting`, `SessionCanvas`, `TranscriptCanvas`) checks registration status on load and redirects unregistered users to UserLanding.

**Implementation Pattern (Reusable):**
```csharp
protected override async Task OnInitializedAsync()
{
    var requestId = Guid.NewGuid().ToString("N")[..8];
    
    // STEP 1: Validate token
    var isValidToken = await ValidateSessionToken(SessionToken, requestId);
    if (!isValidToken)
    {
        // Redirect to error page or home
        Navigation.NavigateTo("/", forceLoad: true);
        return;
    }
    
    // STEP 2: Check registration status
    var isRegistered = await CheckParticipantRegistration(SessionToken, requestId);
    if (!isRegistered)
    {
        Logger.LogWarning("[REGISTRATION-GUARD] Unregistered access attempt - redirecting to UserLanding");
        Navigation.NavigateTo($"/user/landing/{SessionToken}", forceLoad: true);
        return;
    }
    
    // STEP 3: Proceed with normal page initialization
    await InitializeSessionAsync(requestId);
}
```

**Key Methods to Add:**
1. `CheckParticipantRegistration(string token, string requestId)` → `bool`
   - Retrieves UserGuid from localStorage
   - Calls `/api/participant/session/{token}/me?userGuid={guid}`
   - Returns `true` only if participant exists in database

2. `ValidateSessionToken(string token, string requestId)` → `bool`
   - Calls `/api/participant/session/{token}/validate`
   - Returns `true` if token is valid and not expired

- **Low**: Browser privacy modes may disable localStorage

**Mitigation:**
- Use session-token-specific keys: `noor_user_registration_{token}`
- Add try-catch blocks for all localStorage operations
- Graceful degradation if localStorage is unavailable
